# 모바일 검증

현재 저장소의 네이티브 대상은 Android다. iOS 프로젝트는 포함되어 있지 않다.

## 반영한 처리

- Capacitor `appStateChange`로 백그라운드에서 연결을 닫고 포그라운드에서 복구한다. 백그라운드 전환은 방 나가기 API를 호출하지 않는다.
- `networkStatusChange`로 오프라인 복구와 Wi-Fi/셀룰러 전환 시 연결을 다시 만든다. 백그라운드에서는 네트워크 이벤트로 연결을 열지 않는다.
- JS 타이머가 정지되더라도 서버 마감 시각은 진행한다. 화면은 복구 상태의 절대 마감 시각에서 남은 시간을 계산한다.
- 앱 내부 호스트 `suhat.kr`는 기존 저장 데이터와 세션 호환을 위해 유지한다. Android WebView에서 `https://suhat.kr/api/` 요청만 로컬 asset 처리에서 제외해 실제 HTTPS 응답을 받도록 한다. `/api/` 이외의 앱 경로는 Capacitor가 처리한다.
- REST·SSE·쿠키 처리는 같은 API 기준 주소를 사용한다. 세션 원문을 출력하던 로그는 제거했다.

호스트를 `localhost`로 바꾸면 기존 origin의 localStorage와 사용자 정보가 이어지지 않을 수 있어 경로 분리 방식을 선택했다. 네이티브 HTTP의 일반 요청 API로 SSE 전체 응답을 읽지 않고, 기존 WebView 스트림을 유지한다.

## 확인한 범위

설치된 Capacitor 6의 Android bridge와 WebViewLocalServer 구현, Manifest와 네트워크 설정을 확인했다. 앱 상태·네트워크 이벤트는 플러그인 mock 테스트로 검증한다. 이 테스트는 Android WebView의 실제 쿠키·스트리밍 동작을 대체하지 않는다.

Android SDK와 API 34 에뮬레이터를 구성해 디버그 APK 빌드·설치·실행을 확인했다. 임시 HTTPS 터널과 H2 메모리 DB를 사용하는 실제 Spring Boot 서버로 네이티브 세션과 SSE를 검증했다. 물리적인 휴대폰과 iOS 동작은 검증하지 않았다. OS가 앱 프로세스를 종료한 뒤의 자동 방 복귀는 지원하지 않는다. 일반 백그라운드 복귀와 구분한다.

## 기기 검증 순서

```sh
npm ci
npm run build
npx cap sync android
cd android
./gradlew assembleDebug
```

서버와 앱을 함께 업데이트한 테스트 환경에서 3~4대로 확인한다.

| 상황 | 기대 결과 |
|---|---|
| 발언 중 홈 버튼 후 30초 내 복귀 | 같은 카드·발언자, 경과한 시간이 반영된 타이머 |
| 발언자가 끊긴 상태에서 시간 만료 | 다른 참가자가 서버 이벤트로 투표 화면 진입 |
| 청취자 오프라인 후 투표 마감 | 기권 처리, 나머지 투표와 한 번만 집계 |
| Wi-Fi에서 셀룰러로 전환 | 재연결, 점수 중복 증가 없음 |
| 3분 초과 후 복귀 | 게임 종료, 남은 참가자는 대기방 이동 |
| 화면 잠금 후 복귀 | 재접속 유예와 서버 마감 규칙 적용 |
| 명시적 나가기·Android 뒤로가기 | 확인 후 퇴장, 재접속 시도로 되돌리지 않음 |
| SSE 최초 연결 | HTML이 아닌 `text/event-stream`, 세션 유지 |

업데이트 설치 시 기존 로그인 정보가 유지되는지도 확인한다. 인증 실패나 HTML 응답이 발생하면 API 호스트, 쿠키 도메인, WebView 요청 경로, 프록시 SSE 버퍼링을 순서대로 점검한다.

임시 도메인을 사용할 때는 [테스트 서버 설정](test-server.md)에 따라 API 주소, WebView 호스트, 서버 쿠키 도메인을 맞춘다. 센터 서버는 하나의 게임 프로세스로 운영한다.

## 실행 검증에서 확인한 수정

서버 JSON의 발언자 필드는 `speaking`이다. 화면이 `isSpeaking`을 읽어 발언 화면이 비던 문제를 수정하고 서버 응답 형태를 입력하는 컴포넌트 회귀 테스트를 추가했다.

## Android 14 에뮬레이터 실행 결과

Pixel 6 프로필의 Android 14(API 34) 에뮬레이터에 디버그 APK를 설치했다. 앱 한 대와 API 테스트 참가자 두 명으로 3인 게임을 진행했다. 계정과 게임 준비는 테스트 자동화로 구성했고, 앱은 실제 Capacitor HTTP·쿠키·Network·App 플러그인과 WebView SSE를 사용했다. 전체 가입·설문·바코드 스캔 화면을 순서대로 수행한 검증은 아니다.

- 임시 HTTPS 주소에서 세션 유지와 `text/event-stream` 수신 확인
- 발언자·카드·서버 마감 시각 표시 확인
- 홈 버튼 후 복귀: 연결이 닫혔다 다시 열리고 같은 카드와 마감 시각 복원
- Wi-Fi와 데이터 연결 차단 후 복구: 연결 복구 안내 및 최신 상태 수신
- 발언자 백그라운드 상태에서 180초 만료: 다른 참가자에게 투표 이벤트 전달, 앱 복귀 시 투표 화면 표시
- 투표 미제출 2명: 기권 2표, 비동의 0표, 재투표 상태 확인

이 결과는 물리적 휴대폰의 제조사별 절전 정책, 실제 셀룰러 핸드오버, 카메라·바코드 인식 검증을 포함하지 않는다. 서버는 H2 테스트 DB이므로 운영 MySQL 데이터 호환 검증과도 구분한다.

재접속 유예 만료 후 남은 참가자 2명의 방 상태가 `WAITING`으로 전환됐고, 복귀한 앱은 `/game/home`으로 이동했다.
